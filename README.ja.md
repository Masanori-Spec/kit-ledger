# Kit Ledger

**在庫スナップショットから、つくれるキット数と作業用ピックシートへ。**

複数種類のワークショップキットを、共通部品から組み立てるための小さなローカル計画ツールです。予約済み在庫を使わず、希望数を上限に製作数を計算します。

[English](README.md) · [入力仕様](docs/input-contract.md) · [設計と制限](docs/design.md) · [検証状況](docs/verification.md)

## できること

- JSON 1ファイルで在庫・予約数・1階層のレシピ・希望数を読み込む
- 「完成キット総数の最大化」または「レシピの優先順位」で厳密な組合せを選ぶ
- 全希望数をつくるための部品不足を表示する
- バッチ番号付きピックシートHTML、残り在庫CSV、ピック一覧CSV、計画JSONを保存する
- 「在庫 = 予約済み + 使用 + 未予約の残り」を各部品で検証する
- 同じ計算エンジンを日本語／英語ブラウザー画面とCLIで使う

在庫の実更新、発注、アカウント管理、価格、利益、作業者の能力、多階層の組立には対応しません。入力スナップショットと実際の在庫を照合してから作業してください。

## 例でわかる目的の違い

予約分を除いた袋は8枚、マーカーは12本です。スターターは1キットにマーカー1本、デラックスは3本を使います。希望数はスターター8、デラックス4です。

- 総キット数を最大化: スターター8、デラックス0、合計8
- デラックスを最優先: スターター0、デラックス4、合計4

優先順位モードは、総数よりも先頭レシピの製作数を優先します。同数時だけの優先指定ではありません。全希望数に対する不足は、袋4枚・マーカー8本です。

## 起動

Node.js 22または24を使用してください。計算とCLIに外部依存ライブラリはありません。

```sh
node src/cli.mjs examples/workshop.json
node src/cli.mjs examples/workshop.json --out ./my-new-plan --lang ja
node scripts/build.mjs
node scripts/serve.mjs
```

ブラウザーで `http://127.0.0.1:4176` を開きます。画面右上から日本語を選択できます。画面のHTMLをファイルとして直接開くのではなく、ローカルHTTPサーバーを使ってください。

CLIの出力先は、まだ存在しないフォルダーを指定します。既存ファイルは上書きしません。保存したピックシートHTMLは、ブラウザーで開いて通常の印刷機能で印刷できます。

## 制限と安心材料

入力128 KiB以下、レシピ1〜6種、部品1〜100種、希望数は各0〜100。組合せ数の積 `(希望数 + 1)` が20万通りを超える場合は、探索前にエラーにします。ブラウザーでは8秒で中止します。近似解や未完了の計画は出力しません。

数量は `12` のような通常の整数JSON表記のみです。`12.0`、指数表記、重複キー、不明なフィールド、存在しない部品参照、不正な数量は拒否します。

処理はブラウザータブ内で完結します。アプリの読み込み後にデータ送信APIや解析用通信を使わず、入力をアプリ内の永続ストレージへ保存しません。必要な計画は自分で保存してください。入力変更や中止の後に古い計画を保存できないよう、結果と出力を無効化します。

検証の詳細、ブラウザーテスト未実行の環境制約、既存製品との位置付けは英語の各文書に記載しています。独自性や需要が検証済みであるという主張はしていません。
